# 微博宽屏版（weibo-wide）

一个 Tampermonkey 用户脚本，让 `weibo.com` 的正文区域跟着浏览器窗口自适应变宽，而不是永远挤在中间那条 600 多像素的窄栏里。

在竖屏显示器上尤其明显：微博原生布局把内容锁死在约 872px，屏幕再宽也不会用，两侧全是空白。

## 解决什么问题

微博 Web 版的正文列是固定宽度的。屏幕越宽，浪费越多——1379px 的视口下，正文只用了 642px，剩下 700 多像素纯属留白。

网上已有的宽屏脚本（本脚本 fork 自其中一个，见文末）思路是用 JavaScript 监听窗口变化、实时算出目标宽度、再写成固定 px 塞进 DOM。这套做法有几个绕不开的毛病，在竖屏 + 频繁缩放窗口的场景下会集中暴露：

**卡片宽窄不齐、页面横向滚动。** 这是最刺眼的一个。旧版把 `_wrap_ecgcn_2` / `_normal_ecgcn_34` 当成"热门页的主容器"写进了全局 CSS 规则，但这两个是微博 `woo-panel` 组件的哈希类名——**在首页，它们命中的是每一条微博卡片**。那条规则给每张卡片加了 `flex: 0 0 auto`（不许收缩）和 `max-width: none`（去掉微博自己的宽度上限），于是每张卡片都按自己内容的自然宽度撑开：短文本的缩成 358px，含长链接或宽图的撑到 2153px。实测视口 819px 时同屏六张卡片的宽度是

```
358 / 507 / 559 / 749 / 1742 / 2027 / 2153      页面横向滚动到 2195px
```

**缩放跟不上。** JS 算出来的是固定 px，外层容器却是 CSS 百分比自适应的。两套机制只要有一次没对上，宽度就错开——200ms 防抖期间、SPA 切路由时 feed 还没挂载导致函数直接 return、虚拟滚动换掉 DOM 让"还原上次拉伸"记录的元素引用全部失效、滚动条出现或消失根本不触发 `resize` 事件。

**窄窗口下右栏溢出。** 旧版用 `右栏宽度 < 可用宽度 × 0.5` 判断要不要给右栏留位置，视口 ≤634px 时这个条件自己就不成立了，于是正文按"没有右栏"算宽度、右栏却还实打实占着 282px。

## 这个版本怎么做的

把宽度计算**整个从 JavaScript 拿掉**，全部交给 CSS 弹性布局。JS 只保留菜单交互。

浏览器的 flex 布局本来就是实时计算的：没有防抖、不会失步、SPA 换页也不需要谁去"重新计算"。核心是三条：

- 正文列 `flex: 1 1 auto` —— 吃掉右栏之外的全部剩余宽度；
- 右栏 `flex: 0 0 282px` —— 固定宽度不参与伸缩，放不下时由媒体查询整体收起；
- 卡片选择器**限定在热门页**（通过 `<html>` 上的 `weibo-wide-hot` 类），首页绝不生效。

还有一个不容易发现的瓶颈：外层内容区和布局行之间夹着一个**没有任何 class 的 `<div>`**。它是 flex item 但 `flex: 0 1 auto`，不会跟着父容器长大，把整条链卡死了：

```
._content_1ubn9_18        1309px    ← 外层，已经是全宽
  └─ <div>（无 class）      620px    ← 瓶颈在这里
      └─ main._wrap_1l406_3 620px
          ├─ ._full_1l406_7  330px   ← 正文列被挤成这样
          └─ ._side_1l406_17 282px
```

没有 class 就没法用类选择器命中，只能按结构匹配，`:has()` 正好干这个：

```css
._content_1ubn9_18 > *:has(._wrap_1l406_3) { flex: 1 1 auto !important; }
```

顺带修的还有：留白用 `calc(100% - 70px)` 而不是 `100vw`（`100vw` 把滚动条宽度也算进去，实际留白会少约 15px）；样式在 `document-start` 就注入，不会先闪一下原始窄栏；隐藏顶栏按钮的扫描给每个元素加了"只查一次"标记，不再在无限滚动时反复触发强制重排。

## 效果

视口 1379px 的首页，正文列宽度：

| | 正文列宽度 |
|---|---|
| 微博原生 | 642px |
| 旧版 2.6.3 | 615px（比不装还窄） |
| **本版 3.2.0** | **1011px** |

拖动窗口，双向跟随，全程零 JavaScript 参与：

| 视口 | 内容区 | 左右留白 | 正文列 | 右栏 | 卡片是否齐平 | 横向溢出 |
|---|---|---|---|---|---|---|
| 1379 | 1309 | 35 / 35 | 1011 | 282 | 是 | 否 |
| 1059 | 989 | 35 / 35 | 691 | 282 | 是 | 否 |
| 779 | 709 | 35 / 35 | 411 | 282 | 是 | 否 |

每一档都精确满足 `正文列 = 内容区 − 右栏 − 列间距`。

## 安装

1. 装 [Tampermonkey](https://www.tampermonkey.net/)（Chrome / Edge / Firefox 都有）
2. 点这个链接直接安装：[weibo-wide-collapsible.user.js](https://raw.githubusercontent.com/xiezhaoye/tools/main/userscripts/weibo-wide/weibo-wide-collapsible.user.js)
3. 打开 <https://weibo.com> 即可

> **从旧版升级的注意事项**：Tampermonkey 存的是它自己的副本，改磁盘上的文件不会生效，需要在 Tampermonkey 编辑器里用新内容整个覆盖旧脚本再保存。另外旧版的 `@updateURL` 指向 Greasy Fork 的原脚本，自动更新会把改动覆盖回去——本版已改为指向本仓库。

## 顺带带的几个界面改动

这些是从原脚本继承下来的，不是宽屏必需的：

- 左上角 logo 换成汉堡菜单图标（橙色），点击展开左侧导航为悬浮层，点选项或点页面任意处自动收回
- 隐藏顶栏的「视频」「消息」两个入口

不想要可以直接删掉脚本里对应的函数（`mountButtonAtLogo` / `hideNavItems`）。

## 可调配置

都在文件开头的 `可调配置` 区块：

| 常量 | 默认 | 说明 |
|---|---|---|
| `CONTENT_MAX` | `1600` | 内容区最大宽度，超宽屏上限 |
| `SIDE_PAD` | `35` | 内容区左右留白，各 35px |
| `FEED_MIN` | `320` | 正文列最小宽度 |
| `RIGHT_W` | `282` | 右侧热搜栏宽度 |
| `RIGHT_HIDE_BELOW` | 自动算出 `688` | 视口窄于此值时收起右栏；设为 `0` 则一直保留 |
| `MENU_BG` | `#fff` | 悬浮菜单背景，深色模式可改 `#1e1e1e` |

## 已知限制

- **依赖微博的 CSS 哈希类名**（`_content_1ubn9_18`、`_full_1l406_7` 等）。微博前端重新发版时这些类名会变，脚本随之失效，需要重新抓一遍类名。
- **`:has()` 需要较新的浏览器**：Chrome/Edge 105+、Safari 15.4+、Firefox 121+。不支持的浏览器上，热门页的正文列不会变宽，其余功能正常。
- **右栏收起的媒体查询（≤688px）没有在真实微博上验证过**，只在本地仿真页面上逐档验证过切换点和溢出情况。
- 只在微博 Web 版首页和热门页验证过，其他页面（个人主页、搜索结果等）未测试。
